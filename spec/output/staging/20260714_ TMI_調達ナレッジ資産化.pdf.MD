## TMI調達室における現状課題

CP対応業務は約10ステップ、ベテラン依存・情報分散・継承困難という三重苦が存在する。

### CP対応業務フロー（約10ステップ）

| # | ステップ |
|---|---|
| 01 | 要件受領 |
| 02 | 市場調査 |
| 03 | ベンダー選定 |
| 04 | RFP作成 |
| 05 | 見積取得 |
| 06 | 見積評価・比較 |
| 07 | 稟議作成 |
| 08 | 契約審査 |
| 09 | 契約締結 |
| 10 | 事後管理 |

### 主な課題

| 課題 | 内容 |
|---|---|
| 属人化 | ベテラン担当者への依存・判断の属人化 |
| 再利用困難 | 過去案件・判断基準の再利用が困難 |
| 情報分散 | 契約書・見積書・稟議書・メール・Teamsに散在 |
| 継承困難 | 業務継承・人材育成の難しさ |
| 品質ばらつき | 担当者により判断品質にばらつき |

リソース制約：少人数での多様案件対応 ― ナレッジの組織的蓄積・活用が急務

## 調達業務の知識を会社の資産へ

短期の省力化から始め、中期でナレッジ基盤を構築し、長期で調達AIエージェントへ発展させる3段階構想。

| 段階 | テーマ | 主な技術要素 |
|---|---|---|
| 短期 | 業務省力化 | Microsoft 365 Copilot活用、過去資料の検索性向上、Copilotによる文書作成支援 |
| 中期 | ナレッジ基盤化 | SharePoint・Microsoft Graph、Microsoft Fabric、Azure Storage |
| 長期 | 調達AIエージェント | Azure AI Foundry、Azure OpenAI・Azure AI Search、判断支援・自律エージェント化 |

出発点は「ツール導入」ではなく「知識の資産化」――調達ナレッジを組織の財産として蓄積することが、AIエージェント化への確実な道筋。

## Azure AIを活用した調達AI活用ロードマップ

Phase 1〜4の段階的実装で、業務効率化から自律型AIエージェントまで進化させる。
段階的進化: 業務効率化 → ナレッジ資産化 → AI検索・判断支援 → 自律型AIエージェント
各フェーズは段階的に積み上げる設計――前フェーズの成果が次フェーズの基盤となる。

| フェーズ | テーマ | 主要技術 |
|---|---|---|
| Phase 1 | 業務効率化 | Microsoft 365 Copilot |
| Phase 2 | ナレッジ資産化 | SharePoint、Microsoft Graph、Fabric、Azure Storage |
| Phase 3 | AI検索・判断支援 | Azure AI Foundry、Azure OpenAI、Azure AI Search |
| Phase 4 | 調達AIエージェント | Azure AI Agent Service、Power Platform、Fabric |

## Work IQで調達業務の実態と属人化ポイントを可視化

Work IQは「誰が・何を・どう判断しているか」を数値とグラフで見える化する。

### Work IQとは

業務シグナルを統合する「AIの燃料」。メール・会議・チャット・ドキュメントの業務シグナルを統合し、「どう仕事が回っているか」を理解するための基盤データ。

### 調達業務への適用例

- CP対応における意思決定者・承認者・連絡経路の可視化
- 業務集中度（誰に業務が偏っているか）のヒートマップ
- ナレッジが多く眠っている担当者・部門の特定

「見えないものは、変えられない。Work IQで調達業務を"見える化"する」

### 可視化の3つの価値

1. **属人化ポイントの特定 → ナレッジ抽出対象の優先順位付け**
   暗黙知を持つ担当者・業務領域を特定し、ナレッジ化すべき対象を明確化する
2. **業務フローの実態把握 → AI導入効果の最大化**
   実際の業務の流れを可視化し、AIが最も効果を発揮するポイントを特定する
3. **決定根拠・エスカレーション経路の文書化**
   過去の判断プロセスとエスカレーション経路を記録・文書化し、組織知識として蓄積する

## Work IQからAzure AI活用への発展シナリオ（5ステップ）

Work IQで得た業務インサイトを起点に、AIが使える形の知識へ段階的に変換する。

| Step | テーマ | 内容 | 主な技術 |
|---|---|---|---|
| Step 1 | 業務シグナル収集 | M365の活動ログ・コミュニケーションデータを自動収集 | Work IQ |
| Step 2 | 属人化ポイント特定 | 調達室内の業務集中度・暗黙知保有者をマッピング | Work IQ分析 |
| Step 3 | ナレッジ抽出・構造化 | 対象担当者のメール・ドキュメントからFAQ・判断基準を抽出 | AI抽出 |
| Step 4 | ナレッジベース構築 | SharePoint・OneLakeにナレッジを集約、検索可能な形に整備 | Azure AI Foundry / Foundry IQ |
| Step 5 | 調達AIエージェントへ発展 | 蓄積されたナレッジを「燃料」に、AIが調達業務を自律支援 | Foundry IQ + Fabric IQ |

## 調達ナレッジプラットフォーム全体アーキテクチャ

データ層からエージェント層まで、Microsoftの一貫したスタックで実現できる。

### データ層（Sources）

| ソース | 内容 |
|---|---|
| 調達メール・Teams | CP対応メール・Teamsチャット・会議録 |
| 契約書・規程文書 | 契約書・調達規程・ガイドライン・承認記録 |
| 基幹DB・ERP | 仕入先マスタ・発注データ・ERP連携データ |

### ナレッジ層（Knowledge Base）

| コンポーネント | 役割 |
|---|---|
| SharePoint / OneLake | 調達ナレッジの統合リポジトリ・一元管理 |
| Azure AI Search | ナレッジのインデックス化・ベクトル検索 |
| Foundry IQ | 適切なナレッジを自動選択・Agentic RAG |

### AI層（Intelligence）

| コンポーネント | 役割 |
|---|---|
| Work IQ | 「誰がどう働くか」の業務コンテキスト把握 |
| Fabric IQ | 「ビジネスデータの意味」を理解・分析 |
| Azure OpenAI | GPT-4o等の大規模言語モデル（LLM） |

### エージェント層（Agent）

| エージェント | 役割 |
|---|---|
| 調達FAQ・ナレッジ検索（初期PoC） | CP対応・規程・判断知見をAIが即答 |
| CP対応支援エージェント | 交渉支援・メール起案・承認プロセス自動化 |
| 仕入先評価・リスク検知 | 仕入先評価・価格交渉・リスク自動検知 |

セキュリティ・ガバナンス: Entra IDによる権限管理 — 全層に適用

## Microsoftとお客様の役割分担

Microsoftは構想・プロトタイプ支援に徹し、本番構築・運用はお客様またはパートナーが担う明確な役割分担。

| 役割 | Microsoft（構想・支援フェーズ） | TMI調達室（お客様・意思決定/本番フェーズ） |
|---|---|---|
| 内容 | 業務課題整理、ユースケース設計、アーキテクチャ検討、プロトタイプ作成、PoC選定支援 | 業務要件の提示、データ整理・提供、ナレッジ化対象の選定、プロトタイプ評価、本番準備 |
