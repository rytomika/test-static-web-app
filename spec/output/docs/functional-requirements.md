## 3. データモデル候補

本アプリは Power Platform / Dataverse を用いず、Azure サービス（App Service + Azure AI Search + Azure OpenAI / Microsoft Foundry）で実装する（[設計要件](design-requirements.md) 参照）。データモデルは Azure AI Search のインデックス設計として整理する。

### Azure AI Search インデックス候補

| インデックス / フィールド | 内容 | 備考 |
| --- | --- | --- |
| ドキュメントID | 一意キー | 要確認: 命名規則 |
| タイトル / ファイル名 | ドキュメント名 | 契約書・規程・過去案件資料等 |
| 本文チャンク | ベクトル検索対象テキスト | チャンク分割方針は実装時に確定 |
| カテゴリ | 過去案件 / FAQ・規程 / 契約書 等 | 検索フィルタ用 |
| 出典パス | 元ファイルの保管場所（SharePoint 等） | 回答の出典表示に使用 |
| 更新日時 | インデックス反映日時 | 鮮度管理 |

## 4. UI 要件

ユーザーは調達室内部の担当者のみ（社内ユーザー、外部公開なし）。architecture スキルの判断基準に加え、ユーザー指定により UI 実装は **Azure Web アプリケーション（App Service）** とする（Power Platform コンポーネントは不採用）。

### Web チャット UI（App Service ホスト）

- チャット形式で質問を入力し、AIの回答と出典を表示する
- 過去案件検索は検索結果一覧 + 詳細表示
- Entra ID によるサインイン認証（社内ユーザーのみアクセス可）

## 5. 自動化要件

### ナレッジ取り込みバッチ / パイプライン候補

- SharePoint 等に保管された調達関連ドキュメントを定期的に取り込み、Azure AI Search のインデックスを更新する処理（実装方式は要確認: Azure Functions / スクリプト実行等）

## 6. AI / 連携要件

Power Platform の Copilot Studio / AI Builder は本スコープでは不採用（ユーザー指定により Azure App Service 上のアプリケーションとして実装するため）。

### Azure AI 基盤

- **Azure OpenAI**（GPT-4o 等）による回答生成
- **Azure AI Search** によるナレッジのインデックス化・ベクトル検索
- 将来的に **Microsoft Foundry Agent Service**（Foundry IQ / Work IQ / Fabric IQ によるグラウンディング）への拡張を想定（[design-requirements.md](design-requirements.md) 参照）

### 外部連携

- SharePoint / Microsoft Graph（ナレッジソースとしての将来連携、初期PoCでは要確認）
- 基幹DB・ERP（仕入先マスタ・発注データ、将来連携・初期PoCではスコープ外）
